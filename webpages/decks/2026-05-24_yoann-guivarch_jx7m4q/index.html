04 · Ce que j'y vois

Ce que j'y vois

center_focus_strong LA CAUSE RACINE

Le vrai problème n'est pas "automatiser". C'est que ton Notion est en silos.

Tu as 4 bases "Suivi paiements" dupliquées par projet (LNDA / Bendjaballah / Vermelin / SCI CELLARD), 2 bases "Tâches" parallèles, 2 bases "Projets" doublonnées, et plusieurs DB silos par chantier.

Tant que les données sont fragmentées, aucune IA ne peut fonctionner correctement. Tous tes tests avec Claude vont continuer à échouer parce qu'il cherche dans le mauvais silo.

trending_up SI RIEN NE CHANGE...

Tu vas accumuler une 5e, 6e, 7e base silo à chaque nouveau chantier. L'effort de migration deviendra impossible.

En septembre 2026, quand tu voudras repartir en prospection, tu chercheras toujours dans 8 endroits différents.

Tu finiras par embaucher une assistante à 2 000€/mois pour faire le tri. Exactement ce que tu veux éviter.

Étape 01 sur 03

Consolider la mémoire

Pourquoi c'est indispensable

Sans bases unifiées, aucune IA ne peut fonctionner correctement. C'est le préalable obligatoire à toute automatisation.

Ce qu'on va y faire
  1. 1. Audit complet des 24 bases existantes + dédoublonnage
  2. 2. Migration silos projets vers bases globales filtrées (Paiements, Lots, Tâches)
  3. 3. Architecture mémoire unifiée 6 BDD core + relations bidirectionnelles
Livrables
  • check_circle 6 BDD core consolidées (Projets · Lots · Paiements · Tâches · Réunions · Carnet d'adresses)
  • check_circle Plan de migration documenté · 8 pages
  • check_circle SOP capture-dispatch pour les nouvelles données
Étape 02 sur 03

Automatiser les 3 workflows

Pourquoi c'est indispensable

Une fois la mémoire propre, les automatisations tiennent dans le temps. Sans cette étape, tu restes le seul à pouvoir alimenter le système.

Ce qu'on va y faire
  1. 1. W1 Transcription chantier (Whisper + Claude + template strict reproductible)
  2. 2. W2 Email vers Tâche/Alerte (Notion Workers + bridge Gmail si Proton sans API)
  3. 3. W3 Situation de travaux vers Validation paiement (extraction + comparaison DPGF)
Livrables
  • check_circle 3 Notion Workers déployés et documentés
  • check_circle Dashboard rentabilité projet (heures x TJM vs facturé vs encaissé)
  • check_circle Doc maintenance Python · accès code source
Étape 03 sur 03

Formation + Run assisté

Pourquoi c'est indispensable

Sans autonomie, tu redeviens dépendant. L'adoption à 100% se joue ici, pas avant.

Ce qu'on va y faire
  1. 1. Formation 2 sessions de 2h (admin Notion + utilisation quotidienne Workers)
  2. 2. Doc maintenance + accès code Workers + procédure de debug
  3. 3. Loop d'amélioration 4 semaines post-livraison (2 visios J+15 et J+30)
